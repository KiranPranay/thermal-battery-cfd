# Parameter matrix for the twelve configurations reported in the paper

All twelve run configurations are derived from `jeong_case1_discharge.yaml` by parameter override — same geometry, same materials, same mesh topology, same solver settings. The overrides are applied during the case-build step by the launcher script (`scripts/build_case.py` + a per-run wrapper). This file documents the exact deltas so any user can rebuild every case cited in the paper from the single reference YAML.

**Fields that vary across the twelve configs:** `T_amb` (ambient / initial temperature, K); the discharge Case (which of Cases 1, 2, 3, 1-1, 2-1, 3-1 in Jeong's Table 2 to activate as the electrochemical source term); optional `rescue_zone` (the presence and depth-restriction of a rescue pyrotechnic on `insulation_A`); and the OpenFOAM I/O settings `writeInterval` and `endTime`.

**Common to all twelve:** OpenFOAM v2412 `chtMultiRegionFoam`; 5° axisymmetric wedge; nine coupled regions; sha `887587fe…` on the electrolyte thermophysicalProperties; primary pyrotechnic burn 9.7957×10⁹ W/m³ over 0.001–0.421 s in every heat pellet; boundary $h_c = 10$ W/m²/K, $\varepsilon = 0.11$, $T_{\rm init} = T_{\rm amb}$; `nOuterCorrectors = 1`; `maxCo = 0.5`, `maxDeltaT = 0.05`, `adjustTimeStep yes`, `writeControl adjustable`.

### How to build a specific case from this matrix

The reference `jeong_case1_discharge.yaml` sets `T_amb = 300 K` (i.e. +26.85 °C), Case 1 discharge, no rescue, `writeInterval = 2.0 s`, and `endTime = 924 s`. To generate any other case, override the fields above via the build script. Example for `phase7a_t_neg40`:

```bash
python3 scripts/build_case.py \
    --config configs/jeong_case1_discharge.yaml \
    --base-dir /tmp/phase7a_t_neg40 \
    --override T_amb_K=233.15 \
    --override endTime=400 \
    --override discharge=none
```

The build script asserts the sha checksum `887587fe…` on the electrolyte thermophysicalProperties before writing any dictionary, enforces the `FoamFile` header check on every generated `fvOptions`, and requires that the `Selecting finite volume options model` echo appears in the launched solver log before any downstream analysis is permitted (pre-flight discipline D1–D3, encoded in the wrapper).

### Rescue zone specification (`phase7c_rescue_depth_t_neg40`, `phase7c_depth_disch_t_neg40`)

The rescue source is applied over the `rescueZone` cellSet, defined as the innermost 3.6 mm slab of each `insulation_A` cap (stack-facing edge). Per wedge, this contains 574 cells on each cap (1148 total), a volume $V_{\rm source} = 5.13 \times 10^{-7}$ m³ = 21.15 % of the total `insulation_A` volume. The rescue source rate is $q_{\rm rescue}$ such that $q_{\rm rescue} \cdot V_{\rm source} \cdot 0.42 = 1087$ J per wedge (same window as the primary pyrotechnic burn, 0.001–0.421 s). The cellSet definition and the `fvOptions` scalarSemiImplicitSource entry are generated by `scripts/generate_fvOptions.py` when the `rescue_zone` field is present.
